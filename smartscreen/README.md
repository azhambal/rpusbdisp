# smartscreen — настольные часы на RoboPeak Mini USB Display

Превращает RoboPeak Mini USB Display (320×240 + тач) в настольные часы с
несколькими страницами, которые листаются свайпом вбок, как StandBy на лежащем
телефоне:

```
стрелочные  ←  цифровые с погодой (дом)  →  календарь  →  небо
```

</p>

Панель стартует с цифровых часов. Пока листаете, сверху видны точки страниц.
Четвёртая страница — небо: путь солнца за день на небе цвета текущего
часа, долгота дня и фаза луны. Всё считается локально, без сети.

## Запуск

```sh
sudo ./install-udev.sh          # один раз: доступ к /dev/fbN и тачу без root
cp clock.example.json ~/.config/ccdisp/clock.json   # координаты, необязательно
python3 -m ccdisp.clock         # держит панель
```

Как служба — шаблон user-юнита в `systemd/`:

```sh
cp systemd/ccdisp-clock.service ~/.config/systemd/user/
systemctl --user enable --now ccdisp-clock
```

Без панели любую страницу можно отрисовать в файл:

```sh
python3 -m ccdisp.clock --png x.png                  # цифровые часы
python3 -m ccdisp.clock --png x.png --page analog    # analog, clock, calendar, sky
```

Переменная `CCDISP_DEBUG=1` включает лог касаний и переходов между страницами.

## Жесты

* Свайп вбок — соседняя страница. Достаточно протащить палец на треть ширины
  или коротко и быстро смахнуть. Короткое медленное движение возвращает страницу
  на место, а за крайней страницей она пружинит.
* Касание цифровых часов — немедленно обновить погоду.
* Вертикальное движение страницы не листает.

Анимация короткая (0.28 с) и рассчитана по времени, а не по кадрам: панель
висит на USB full speed, и `fb_defio` отправляет кадр не чаще 16 раз в секунду.
На медленной отправке будет меньше промежуточных кадров, но жест не затянется.

## Устройство

```
/dev/input/eventN --> touch.py --> pager.py --> страница.frame() --> fb.py --> /dev/fbN
```

* `ccdisp/clock.py` — точка входа: собирает страницы, крутит селекторный цикл.
* `ccdisp/pager.py` — жесты, перетаскивание, анимация, точки страниц. Страницы
  про соседей и про сдвиг ничего не знают: каждая рисует себя целиком.
* Страницы — `analog.py`, `clockface.py` (цифровые часы с погодой),
  `monthview.py`, `sky.py`. Контракт один: `frame()` возвращает `None`, пока
  прошлый кадр верен, а `timeout()` говорит, когда это перестанет быть так.
  Поэтому секунды, в которые ничего не изменилось, ничего не стоят.
* `ccdisp/theme.py` — цвета, шрифты, русские названия дней и месяцев.
  Скруглённое и наклонное рисуется в 3× и уменьшается: у Pillow нет сглаживания.
* `ccdisp/weather.py` — Open-Meteo в фоновом потоке.
* `ccdisp/config.py` — `~/.config/ccdisp/clock.json` и определение координат.
* `ccdisp/fb.py`, `ccdisp/touch.py` — железо.

`"analog_seconds": false` в конфиге убирает секундную стрелку: стрелочные
часы тогда перерисовываются раз в 10 секунд, а не каждую.

В календаре подсвечены выходные и праздники РФ с фиксированными датами.
Переносы выходных не показываются: их утверждают каждую осень, и офлайн-правила
для них нет.

## Часы и погода

Погода — Open-Meteo: без ключа и без регистрации, иначе «просто часы» начинались
бы с заведения аккаунта. Запрос уходит раз в 10 минут из отдельного потока:
селекторный цикл часов владеет экраном и не имеет права стоять в ожидании
чужого сервера. Касание по цифровым часам просит обновиться немедленно.

Координаты берутся из `~/.config/ccdisp/clock.json` (см. `clock.example.json`).
Без файла они один раз определяются по IP (`ipapi.co`, затем `ip-api.com`) и
кэшируются в `~/.cache/ccdisp/location.json` — так свежая установка показывает
свой город, но VPN не таскает панель по странам каждые десять минут.
`"geolocate": false` запрещает и этот единственный запрос.

Если ответа нет, на экране остаётся последнее значение; старше трёх часов —
блок гаснет и вместо «ощущается» появляется время последнего замера. Часы при
этом идут: погода не должна уносить с собой и время.

Иконки рисуются примитивами, а не шрифтом: у DejaVu нет пригодных глифов
погоды, а круги и линии переживают уменьшение до 18 px в строке прогноза.

## Что выяснилось про железо

* Панель — **BGR565**, красный в младших битах (`red.offset = 0`). В Pillow 12
  режима `BGR;16` и raw-упаковщика 565 больше нет, поэтому `Framebuffer.pack()`
  собирает оба байта пикселя таблицами `point()` и склеивает их через `LA`.
  Раскладка читается из `FBIOGET_VSCREENINFO`, не захардкожена.
* Ноды искать по именам: `rpusbdisp-fb` в `/sys/class/graphics`,
  `RoboPeakUSBDisplayTS` в `/sys/class/input`. Номера `fbN`/`eventN` плавают.
* `struct input_event` — 24 байта. В `struct.Struct` формат обязан быть нативным
  (`@llHHi`); под `=` long становится 4-байтовым, событие — 16-байтовым, и поток
  разбирается в труху молча.
* Тач квантуется примерно по 5.5 px по X и 4.2 px по Y — физически около 58×57
  точек на 320×240. Для кнопок нормально, для пиксельной точности нет.
* Драйвер объявляет `ABS_X` как `0..320` (не `0..319`), координату надо зажимать.
* Оба узла создаются без родительского устройства и попадают в
  `/devices/virtual/`, поэтому logind не приписывает их к seat и тег `uaccess`
  сам по себе не работает — отсюда `OWNER=` в udev-правиле.
* `fb_defio` гонит по USB все страницы, которые мы испачкали, а часы
  перерисовываются каждую секунду. Поэтому `Framebuffer.blit_changed()` сравнивает
  кадр с предыдущим и пишет только изменившийся прямоугольник: мигание двоеточия
  — 0.7 % экрана, смена минуты — 8.8 %, вместо 76 800 пикселей каждый раз.
* Чтение `/dev/fbN` обратно в Pillow (`raw`, `BGR;16`, с обратной перестановкой
  каналов) даёт ровно то, что видно на панели, — удобный способ проверить рендер
  без фотографирования экрана. Максимальная ошибка канала 7 — это квантование
  565, а не ошибка упаковки.

## Если экран чёрный

1. `ls /sys/class/graphics/*/name | xargs grep rpusbdisp` — есть ли framebuffer.
   Если нет, смотрите `journalctl -k | grep rp_usb`. Строка
   `disagrees about version of symbol module_layout` означает, что Ubuntu
   переставила ядро с той же строкой версии (`uname -r` не изменился, ABI —
   да), и DKMS посчитал модуль уже собранным. Лечится принудительной пересборкой:

   ```sh
   sudo dkms install rp-usbdisplay/1.0.0 -k "$(uname -r)" --force
   sudo modprobe rp_usbdisplay
   ```

2. Framebuffer есть, а картинки нет — `journalctl --user -u ccdisp-clock`.
   Служба перезапускается по кругу, если упала на первом же кадре.
